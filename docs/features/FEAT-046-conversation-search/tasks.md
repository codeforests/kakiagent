## Build notes

- **B1 — Search reads through `inbox_search_hits()` (T3).** Under RLS, Postgres only uses leakproof operators as index conditions, and `ILIKE` isn't leakproof, so through `app_dashboard` the trigram index could narrow only by tenant and every search rechecked rows by scan (the first volume run: `Seq Scan`, 376–1,049 ms, growing with every tenant's messages). 0047 adds the 0045 pattern: a NOLOGIN role `kaki_inbox_search` (no BYPASSRLS) with SELECT on seven `messages` columns under an always-true policy for that role only, and a SECURITY DEFINER `inbox_search_hits(patterns text[])` that filters `tenant_id = app_current_tenant()` itself and returns the latest matching message per conversation; EXECUTE for `app_dashboard` only. `searchConversations` joins it to `conversations` (RLS as before) and filters both on the tenant explicitly. Contract unchanged. Covered in `rls.int.test.ts` (tenant A/B/none, other zones denied, role can't log in, column grants). For the verify stage to check against ADR-005.
