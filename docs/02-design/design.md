# Design System: KakiAgent

> Source of truth for all UI implementation, together with [tokens.json](tokens.json).
> Generated by ux-foundations · Mode: research · Direction: **Harbour**
> Last updated: 2026-10-19 · Plan-time companion: [ux-foundations.md](ux-foundations.md)

This file covers all three UI surfaces: the **Dashboard and Inbox PWA** (`APP`), the **Widget** (`WGT`) and the **Operator console** (`OPS`). Section 4.9 holds the per-surface variants. Requirement IDs resolve in [SRS.md](../01-requirements/SRS.md); ADR IDs resolve in [adr/](adr/).

---

## 1. Visual theme and atmosphere

**Calm, precise, trustworthy.** An SME owner opens KakiAgent to check whether the bot said the right thing and what needs their decision. The interface earns trust by being quiet. Neutral slate surfaces carry the content. The sea-teal accent appears only where the user can act: the primary button, the selected item, a link. Status colours (green, amber, red, blue, violet) are kept strictly for state, so "approved" never looks like decoration and "needs review" always stands out.

Density is moderate. The dashboard is a work tool used in short bursts, often on a phone, so lists are scannable, not cramped. Prices, dates and counts use tabular numerals. Provenance is always visible: a fact is shown next to the passage it came from, and an answer next to the facts it used. The look is close to Stripe's dashboard and avoids anything playful. Governance screens (audit, PDPA, kill switch) use the same calm voice as everything else and never alarm by default.

### 2.2 Typography

- **Family:** IBM Plex Sans (OFL), self-hosted from the dashboard's own origin as WOFF2 (400, 500, 600 plus 400 italic, Latin subset). It's never loaded from Google Fonts at runtime. The stack falls back to PingFang SC → Hiragino Sans GB → Noto Sans SC → Microsoft YaHei for Simplified Chinese content (conversations are EN, Singlish and 中文 — AGT-03), then system UI.
- **Mono:** IBM Plex Mono for snippets, DNS records, IDs, hashes and the audit chain. Never use it for prose.
- **Numbers:** `font-variant-numeric: tabular-nums` on every price, count, time, KPI and table column of numbers.

| Step | Token prefix | Size / line | Weight | Usage |
|---|---|---|---|---|
| caption | `--type-caption-*` | 12 / 16 | 400 | Timestamps, chip text, meta |
| body-sm | `--type-body-sm-*` | 13 / 18 | 400 | Dense tables, sidebars |
| body | `--type-body-*` | 14 / 20 | 400 | Default dashboard text |
| body-lg | `--type-body-lg-*` | 16 / 24 | 400 | Chat messages; all inputs on touch (prevents iOS zoom) |
| title-sm | `--type-title-sm-*` | 16 / 24 | 600 | Card titles |
| title | `--type-title-*` | 20 / 28 | 600 | Section headings |
| heading | `--type-heading-*` | 24 / 32 | 600 | Page titles |
| display | `--type-display-*` | 30 / 38 | 600 | Home KPIs, wizard step titles |
| code | `--type-code-*` | 13 / 20 | 400 mono | Snippets, records |

Rules: weight 500 is for buttons, tabs and table headers; 600 for titles only. Never use weight 700. Headings use `text-wrap: balance`. Body text is at most 72ch wide. Uppercase is used only for 12px overline labels with `letter-spacing: 0.04em`.

### 2.3 Spacing, radius, elevation, motion

- **Spacing (4 px base):** `--space-1` 2 · `-2` 4 · `-3` 8 · `-4` 12 · `-5` 16 · `-6` 20 · `-7` 24 · `-8` 32 · `-9` 40 · `-10` 48 · `-11` 64 px. Inside a component: 8–16. Between components in a card: 12–16. Card padding: 16 (mobile) / 20 (≥ md). Between sections: 32. Page padding: 16 (mobile) / 24 (≥ lg).
- **Radius:** `--radius-sm` 4 (checkbox, code) · `-md` 6 (buttons, inputs, menus) · `-lg` 8 (cards, popovers) · `-xl` 12 (dialogs, sheets, chat bubbles) · `-full` (pills, avatars, toggles).
- **Elevation:** flat by default, with borders separating surfaces. `--shadow-sm` for sticky bars, `--shadow-md` for menus, popovers and toasts, `--shadow-lg` for dialogs, sheets and the widget panel. Cards have a border and no shadow.
- **Motion:** `--duration-fast` 120 ms (hover, toggles) · `-base` 180 ms (menus, toasts) · `-slow` 260 ms (sheets, dialogs, widget panel). Easing: `--easing-standard`, `--easing-enter` on enter and `--easing-exit` on exit. Under `prefers-reduced-motion: reduce`, all durations become 0 ms except opacity fades ≤ 120 ms. Nothing loops except the loading spinner and the streaming indicator.

### 2.4 Iconography

**Lucide** (ISC), outline, stroke 1.75, 16 px inside controls and 20 px standalone, coloured `currentColor`. An icon-only button always has an `aria-label` and a tooltip. Status chips pair colour with an icon (✓ approved, ! needs review, ⚠ conflict, ⏸ paused) so state never relies on colour alone. The widget inlines only the SVGs it uses (≤ 8 icons) to stay within its budget.

## 3. Layout and grid

**Breakpoints:** `sm` 640 · `md` 768 · `lg` 1024 · `xl` 1280 px, mobile-first (`min-width`). The smallest supported width is **375 px** with no horizontal scrolling (INB-06).

**Dashboard shell (APP)**

| Width | Navigation | Content |
|---|---|---|
| < 768 | Top bar 56 px (tenant name, AI status pill, avatar) + **bottom tab bar** 64 px + safe-area inset: Home · Inbox · Approvals · Review · More | Single column, 16 px gutters. List → detail pushes a full-screen view with a back button |
| 768–1023 | Collapsed sidebar 64 px (icons + tooltips) + top bar | Single column, or list + detail where the screen defines it |
| ≥ 1024 | Sidebar 240 px (collapsible to 64) + top bar | Content up to 1200 px for settings and forms (720 px for single forms); lists and inbox use full width |

- **Inbox:** ≥ 1280: three panes (list 360 px · thread flexible · context sidebar 320 px). 1024–1279: two panes, with the sidebar as a right drawer. < 1024: one pane at a time.
- **Review · Facts and Conflicts:** a single-column queue of self-contained cards (max 880 px) at every width. Edit and approve opens a dialog (bottom sheet below 640 px), not a detail pane (anchor amendment A1).
- **Review · Corrections and Knowledge lists:** ≥ 1024 list + detail split (list 420 px); smaller: list, then a full-screen detail.
- **Top bar (all widths):** tenant switcher (AUTH-04) · global search (INB-11) · **AI status pill** (Live / Paused / Not live — opens the kill-switch dialog, GOV-08) · help (DSH-10) · notifications · avatar menu.
- **Sticky action bars:** bulk actions and form Save/Cancel stick to the bottom on mobile (above the tab bar) and to the top of the list on desktop.

**Touch targets:** on `pointer: coarse`, every interactive element is ≥ 44 × 44 px (`--size-control-lg`), with ≥ 8 px between adjacent targets. On fine pointers, controls are 36 px (`--size-control-md`), and 32 px only inside table rows.

**Operator console (OPS):** desktop-only (≥ 1024 supported; below that a notice says to use a larger screen). It has a fixed 240 px sidebar and full-width tables.

**Widget (WGT):** see §4.9.

## 4. Components

Components are built on **Radix UI primitives** (ADR-002) for behaviour and accessibility, and styled only with the tokens above. Each spec lists every state. "Focus" always means `outline: 2px solid var(--color-focus); outline-offset: 2px` shown on `:focus-visible`.

### 4.1 Actions

**`button`** — height 36 (44 on touch), padding 0 × 16, radius `--radius-md`, `--type-body` weight 500, icon gap 8.

| Variant | Default | Hover | Active | Disabled | Loading |
|---|---|---|---|---|---|
| `primary` | accent fill, on-accent text | accent-hover | accent-active | 40% opacity, `cursor: not-allowed`, no hover | spinner replaces leading icon, label kept, `aria-busy="true"`, not clickable |
| `secondary` | surface fill, 1 px border-strong, text-primary | subtle fill | subtle fill + inset shadow-sm | as above | as above |
| `ghost` | transparent, text-primary | subtle fill | subtle fill | as above | as above |
| `danger` | danger fill, on-accent text | danger-hover | danger-hover | as above | as above |
| `danger-ghost` | transparent, danger text | danger-soft fill | danger-soft | as above | as above |

Rules: **at most one `primary` per view region.** Destructive actions use `danger` only in their confirming dialog; the button that opens the dialog is `danger-ghost`. Sizes: `sm` 32 (tables, pointer only), `md` 36, `lg` 44.

**`icon-button`** — square, 36 (44 touch), ghost style, `aria-label` required, tooltip on hover/focus after 400 ms.

**`link`** — `--color-text-link`, always underlined (1 px, offset 2 px). Hover: accent-hover. External links add an ↗ icon and open in a new tab with `rel="noopener"`.

### 4.2 Forms

**`field`** = label (body, 500, text-primary) + control + help (caption, text-secondary) + error (caption, danger, with an icon). Label sits above the control with 4 px gap; help/error 4 px below. Required fields are marked "(required)" in the label text, never with an asterisk alone. Optional fields are not marked when most fields are required.

**`text-input` / `textarea` / `select`** — height 36 (44 touch), padding 0 × 12, surface fill, 1 px border-strong, radius md, body text (body-lg on touch). Placeholder in text-secondary, used only for examples ("e.g. 201912345K") and never as a label.
- Hover: border text-secondary.
- Focus: border accent plus the focus ring.
- Error: border danger, `aria-invalid="true"`, error text linked via `aria-describedby`.
- Disabled: subtle fill, text-disabled.
- Read-only: no border, subtle fill.

**`checkbox` / `radio`** — 16 px box, hit area 44 on touch, border-strong. Checked: accent fill with an on-accent glyph. Indeterminate (bulk select): accent fill with a dash.

**`toggle`** (Radix Switch) — 36 × 20, full radius. Off: border-strong track. On: accent track. The label states what *on* means ("AI replies on this channel"). It applies immediately, unless the setting is sensitive (§4.10), in which case it opens a confirmation.

**`combobox` / `multi-select`** (Radix Popover + listbox) — for industry, tags, assignees.

**`date-time` / `hours-editor`** — weekly grid with an open/closed toggle per day plus time ranges. The SG public-holiday list is preloaded with an "open on this day" option per holiday (ONB-03).

**Validation convention (NFR-19):** validate on blur and on submit, never on each keystroke. On submit with errors, an inline `alert` (danger) at the top lists each error as a link to its field, and focus moves to that alert. Error text names the field and the fix: "UEN must be 9 or 10 characters, like 201912345K", not "Invalid input".

### 4.3 Feedback

**`toast`** — bottom-centre on mobile (above the tab bar), bottom-right on desktop. Surface fill, shadow-md, radius lg, max-width 400. Auto-dismisses after 5 s, pausing on hover or focus. `role="status"`. It may hold one action ("Undo"). Never use a toast for errors that need action; use an inline alert.

**`alert`** (inline) — radius lg, soft fill of its status, a 20 px icon, title-sm and body. Variants: info, success, warning, danger. It may include one action link.

**`banner`** (page-wide, under the top bar) — full width, 40 px min height, soft fill, dismissible unless critical. Reserved for:
1. **AI paused** (danger, not dismissible: "AI is paused on all channels. Visitors see your fallback message." [Resume AI]) — GOV-08
2. Trial / plan limit (info or warning) — DSH-07, DSH-08
3. Degraded channel (warning) — CHN-12
4. Support access active (info, not dismissible) — DSH-06
5. Terms re-acceptance needed (warning, Owner) — AUTH-08
6. Tenant scheduled for deletion (danger, Owner; shows the restore action) — AUTH-07

At most two banners show at once, in the priority order above.

**`dialog`** (Radix Dialog) — centred, max-width 480 (640 for previews), radius xl, shadow-lg, scrim behind. On < 640 it becomes a **bottom sheet** (full width, radius xl on top corners, drag handle). Focus moves to the first field or the least destructive action. Esc and the scrim close it unless an action is in progress.

**`confirm-dialog`** — title states the action as a question ("Approve 42 facts?"). The body states the consequence with counts. Buttons: the cancel action is `secondary` and on the left; the confirm button is on the right and repeats the verb ("Approve 42 facts"). For irreversible actions (delete tenant, PDPA deletion) the user must type the name or the word DELETE.

**`reauth-dialog`** — required before sensitive actions (AUTH-03): "Confirm it's you" → magic link, Google or TOTP. On success the original action continues automatically.

**`spinner`** — 16/20 px ring in currentColor. Shown only after 300 ms, to avoid flicker. **`skeleton`** — subtle fill blocks matching the final layout, shimmer disabled under reduced motion. **`progress`** — determinate bar (accent on subtle) for ingestion, with a text percentage and the step name.

### 4.4 Data display

**`card`** — surface fill, 1 px border-default, radius lg, padding 16/20. No shadow. Clickable cards get a hover border of border-strong and are a single link.

**`chip` / `status-badge`** — height 22, padding 0 × 8, full radius, caption weight 500, soft background plus the `-fg` alias, with a 12 px leading icon. Use the semantic aliases in §2.1 for conversation and fact states. The text is always present ("Needs review"), never colour alone.

**`table`** (desktop) / **`list`** (mobile) — header row in subtle fill, body-sm weight 500, text-secondary. Rows 48 px (40 dense), divider border-default, hover in subtle fill, selected in accent-soft. Sortable headers show an arrow and `aria-sort`. Bulk selection uses a checkbox column; selecting rows reveals the sticky bulk-action bar ("12 selected · Approve · Reject · Clear"). Below 768 px a table turns into a **stacked list**: primary text, then secondary meta, then the status chip on the right.

**`pagination`** — cursor-based "Load more" on mobile lists; numbered pages plus a page-size picker on desktop tables (INB-01).

**`empty-state`** — centred in its container: a 40 px outline icon in text-secondary, a title-sm headline saying what will appear, one sentence of help, and **one primary next action** (NFR-19). Example: "No facts waiting for review. New facts appear here after a source finishes processing." [Add a source]

**`error-state`** — same layout with a danger icon: what failed, in plain words, and [Try again]. If it's partly loaded, show what loaded and an inline alert for the rest.

**`kpi-tile`** (Home) — label (body-sm, text-secondary), value (display, tabular), and a delta against the previous period (caption; success or danger with an arrow; neutral when < 2%). The whole tile is a link to the filtered list.

**`tabs`** (Radix Tabs) — underline style: 2 px accent underline on the active tab, body weight 500. Counts in a neutral pill. Tabs scroll horizontally on mobile, never wrap.

**`avatar`** — 28/32 px circle, accent-soft background, accent initials (or a CJK first character). Contact avatars show a channel badge at the bottom-right (12 px glyph: widget, email, Telegram, Messenger, Instagram).

### 4.5 Navigation primitives

**`nav-item`** (sidebar) — 36 px, padding 0 × 12, radius md, icon 20 plus label. Default: text-secondary. Hover: subtle fill, text-primary. Active: accent-soft fill, accent text and icon, `aria-current="page"`. Count badge on the right (pill, warning-soft for review counts, pending-soft for approvals).

**`tab-bar-item`** (mobile) — 64 px tall, icon 24 plus caption label, active in accent. Count dot or number pill at the top-right of the icon.

**`menu` / `dropdown`** (Radix DropdownMenu) — surface, shadow-md, radius lg, items 36 px (44 touch), danger items in danger text after a divider.

**`breadcrumb`** — only on depth ≥ 3 settings pages, body-sm, text-secondary, with a chevron separator.

**`tenant-switcher`** — a menu listing active memberships only (AUTH-04), with the current one checked.

### 4.6 Domain components (dashboard)

**`quick-coach-panel`** (AGT-17) — a right slide-over, 400 px wide, shadow-lg, opened from Review, Knowledge and Conversation screens with context pre-filled ("Ask about this fact"). ### 4.8 Data-view states (all surfaces, NFR-19)

Every list, table, form and long-running job defines all four states: **loading** (skeleton in the final layout; spinner only for in-place actions), **empty** (`empty-state` with one next action), **error** (`error-state` with retry, keeping any data already loaded), and **populated**. Filtered-empty is different from empty: "No conversations match these filters" [Clear filters]. Permission-limited views say why: "Only the Owner can change the plan."

### 4.9 Per-surface variants

**APP on touch (`pointer: coarse`)** — `--size-control-md` is overridden to 44 px; inputs use body-lg; table rows become stacked list items at least 56 px tall; swipe actions are not used (everything is reachable by tap); bottom sheets replace dialogs and popovers below 640 px.

**OPS** — density override: table rows 40 px, body-sm in tables. A permanent neutral "Operator console" label sits in the top bar, and the sidebar background is `--color-text-primary` with inverted text (the only dark-chrome surface in light mode). This makes it clear at a glance that the operator isn't in a tenant's dashboard.

**WGT (embedded widget)** — runs inside a closed Shadow DOM (ADR-016). It uses **only `--kaki-*` variables**, defined on the shadow host from detection results or the defaults in tokens.json `widget.*`:

| Variable | Default | Detected from (CHN-14) | Clamp |
|---|---|---|---|
| `--kaki-accent` | `--color-accent-default` | Most prominent button or link background on the host page | Adjust lightness (OKLCH) until on-accent text is ≥ 4.5:1 and the accent against the panel is ≥ 3:1; on-accent becomes #FFFFFF or #0B1117, whichever contrasts more |
| `--kaki-font` | system-ui stack + CJK | Host `body` computed `font-family` | Never downloads fonts; falls back to the default if the host font is a decorative or icon font |
| `--kaki-radius` | 12px | Host primary button `border-radius` | 0–20 px; bubbles use radius + 4 px (capped at 20) |
| scheme | light | Host background luminance plus `prefers-color-scheme`, observed live | Light or dark set below |

Fixed widget tokens are bundled at build time as `--kaki-*` aliases of the core colour tokens, with light and dark values (tokens.json `widget.*`; anchor amendment A3): `--kaki-surface`, `--kaki-subtle`, `--kaki-text`, `--kaki-muted`, `--kaki-border`, `--kaki-border-strong`, `--kaki-info-bg` (staff messages), `--kaki-on-accent` (default; replaced by the clamp result). The widget never reads the host's or the dashboard's CSS variables. Status colours are unchanged; typography = body-lg for messages and caption for meta. **Panel:** 380 × min(640 px, viewport − 100 px), radius `--kaki-radius` + 4, shadow-lg, anchored 20 px from the corner chosen in settings. **Below 480 px wide** the panel is full-screen (100dvh) with a sticky header and the composer kept above the on-screen keyboard. **Launcher:** 56 px circle in the accent colour with a chat icon, an unread count badge, and `aria-label` "Chat with {bot name}".

Widget components: `launcher`, `proactive-bubble` (≤ 1 per session, dismissible, AGT-10), `panel-header` (bot name and avatar, "AI assistant" label, menu: Talk to a person · Privacy notice · End chat — CHN-13), `disclosure-row` (first message, AGT-11), `message` (visitor right in the accent colour; bot left on subtle; **verified segments appear sentence by sentence with a typing indicator between them** — no token streaming, ADR-008), `feedback-buttons` (👍/👎 on each bot reply, AGT-15), `consent-card` (purpose statement, Agree / Not now, separate unchecked marketing opt-in — LED-02, LED-08), `lead-form-card` (inline fields, SG phone validation), `handoff-card` (Continue on Telegram / by email — CHN-07), `system-notice` (staff joined, waiting for approval with the expected time, after hours with the return time, AI paused), `rating-card` (end of chat), `attachment-chip` (CHN-09).

### 4.10 Sensitive-action pattern

Actions listed in AUTH-03 (delete tenant, transfer ownership, grant support access, export leads or audit data, PDPA deletion, change boundary rules), plus the kill switch, go-live and Approve all, always follow this sequence: **trigger (`danger-ghost` or `secondary`) → confirm-dialog with consequences and counts → re-auth dialog if AUTH-03 requires it → server acknowledgement → toast with the result (and the audit-log reference where relevant).** They are never one-tap and never optimistic.

## 5. Accessibility rules (non-negotiable)

Standard: **WCAG 2.1 AA** for the dashboard and widget (NFR-09, CHN-02), verified by axe-core in CI with no serious or critical issues allowed (architecture §8.7). The operator console follows the same rules.

1. **Contrast:** text ≥ 4.5:1 (≥ 3:1 for text ≥ 24 px, or ≥ 18.66 px bold); UI component boundaries and focus indicators ≥ 3:1. The token pairs in §2.1 are pre-verified; never put text on a colour pairing that isn't in that table. Widget colours are clamped at runtime (§4.9).
2. **Focus:** always visible on `:focus-visible`: a 2 px `--color-focus` outline with 2 px offset. Never use `outline: none` without this replacement. Focus order follows visual order. Dialogs trap focus and return it to the trigger when closed.
3. **Keyboard:** everything works without a mouse. Lists support arrow keys and Enter, and the review queue has the shortcuts listed in §4.6. A skip link reads "Skip to content".
4. **Targets:** 44 × 44 px on touch; on desktop, 24 px minimum with spacing.
5. **Not colour alone:** every status has text and an icon.
6. **Semantics:** one `h1` per page; landmarks (`header`, `nav`, `main`); real `<button>` and `<a>` elements; form labels tied to their controls; tables use `th scope`.
7. **Live regions:** new inbox messages and widget replies are announced through a polite `aria-live` region (one announcement per verified segment, not per token). Toasts use `role="status"`; errors that block the user use `role="alert"`.
8. **Motion:** honour `prefers-reduced-motion` (§2.3). Nothing flashes more than 3 times per second.
9. **Text resize and reflow:** usable at 200% zoom and at 320 CSS px (WCAG 1.4.10) without loss of content. The layout targets 375 px but must not break at 320.
10. **Language:** `lang="en"` on the dashboard. Each message bubble with Chinese content gets `lang="zh-Hans"` when the detected language is Chinese, so screen readers pronounce it correctly.
11. **Time limits:** SLA countdowns are informative only. Magic-link and session expiry warn before expiring and allow extension where AUTH-02 permits.

## 6. Voice and microcopy

**Voice: plain and warm**, like a capable colleague who respects the owner's time. Use short sentences, everyday words and the active voice. Address the user as "you" and the product as "KakiAgent" or "your assistant". The UI itself never uses Singlish. The bot's tone toward visitors is the tenant's choice (AGT-08) and is separate from the product voice.

| Do | Don't |
|---|---|
| "42 facts need your review before your assistant can use them." | "Pending entity validation queue: 42 items." |
| "We couldn't reach your Telegram bot. Check the token in BotFather, then reconnect." | "Error 401: Unauthorized." |
| "Approve 42 facts?" / "Approve 42 facts" | "Are you sure?" / "OK" |
| "Your assistant is live on your website." | "Woohoo! 🎉 You're all set!!" |
| "Prices are quoted with GST because you're GST-registered." | "GST logic applied." |

- **Errors:** what happened + what to do next, with no blame and no apology filler. Name the field.
- **Success:** state the outcome in past tense ("Approved 42 facts") with an Undo where possible.
- **Empty states:** say what will appear and how to get it.
- **Governance copy** (PDPA, audit, kill switch) is precise and calm: name the regulation only where it helps ("Under the PDPA you have 30 days to respond. Due 18 Nov.").
- **Terminology** stays fixed across all surfaces: *fact* (not entity or item), *source*, *review*, *correction*, *conversation*, *contact*, *lead*, *approval*, *take over* / *hand back*, *go live* / *go offline*, *pause AI* / *resume AI*. Use SGD as "S$58.00", dates as "18 Nov 2026" and times as "2:30 pm" in SGT (NFR-10).
- **Widget defaults** (editable by the tenant except the disclosure core): disclosure "You're chatting with {bot name}, an AI assistant for {business}. A person can take over at any time."; fallback "Our team will get back to you soon. Leave your details and we'll contact you."

## 7. Do's and don'ts

- **Do** use tokens for every colour, space, radius, shadow and duration. Raw hex or px in component code fails review.
- **Do** use the semantic aliases (`--color-fact-*`, `--color-conversation-*`) for states, never raw status colours.
- **Do** show provenance: a fact next to its source passage, an answer next to its facts.
- **Do** put tabular numerals on every number that can line up.
- **Do** design all four data states (§4.8) for every list and job.
- **Don't** use the accent colour for status, or status colours for decoration.
- **Don't** use more than one primary button per region, or make destructive actions primary outside their dialog.
- **Don't** stream raw tokens in any UI. Visitor-facing and staff-facing AI text appears per verified segment (ADR-008).
- **Don't** add new component variants. Extend through the defined axes (variant, size, state) or propose an amendment to this file.
- **Don't** load web fonts or third-party assets in the widget. Only `--kaki-*` variables are allowed there.
- **Don't** hide owner-only or admin-only controls without explanation when a role lacks permission. Show them disabled with a tooltip where discoverability matters (for example, Agents see "Approve" disabled with "Ask the Owner for approval rights").
